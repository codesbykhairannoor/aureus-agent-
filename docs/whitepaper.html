1. Executive Summary & Problem Formulation

The proliferation of autonomous AI trading agents in Web3 has exacerbated a fundamental trust deficit. Traditional algorithmic bots operate as closed black boxes: track records are selectively published via screenshots or private messaging channels, winning calls are retroactively celebrated, and losing positions are deleted or obscured. Furthermore, algorithmic bots execute without programmatic safety ceilings—an unexpected API crash, oracle manipulation, or execution loop hallucination frequently leads to total capital depletion.

Aureus Agent replaces subjective trust with immutable on-chain mathematics natively on BNB Smart Chain (BSC Mainnet). Capital execution is strictly subordinated to smart contracts: predictive calls are cryptographically sealed prior to market moves, portfolio equity is anchored to a non-negotiable circuit breaker contract, and every transaction is audited by a fail-closed pre-flight security solver.

2. The Three Architectural Pillars

Aureus Agent decouples computational market intelligence from financial signing authority. Even if the off-chain neural model produces a flawed signal, the on-chain smart contracts prevent catastrophic execution.

Pillar I: Cryptographic Commit-Reveal Prediction Registry

Deployed at 0xcA9499a2d20cFAa98f9Bc3b2F1386A70f51c2FEB on BSC Mainnet, the CommitRevealPredictionRegistry establishes an audit trail that cannot be backfilled:

  • Commitment Phase (T0): Before submitting an order, the agent generates a cryptographic commitment hash:
    C = keccak256(abi.encodePacked(agentId, symbol, direction, targetPrice, expiryBlock, salt))
    The hash is submitted to BSC Mainnet via commitPrediction(C) and mined into a block, creating an immutable timestamp prior to market resolution.
  • Execution & Lock Phase (T1): The position is opened or simulated. The plaintext prediction remains hidden on-chain to eliminate frontrunning and copy-trading vulnerabilities.
  • Reveal Phase (T2): Once the interval closes, the agent reveals parameters and the secret salt. The contract verifies keccak256(...) == C. Upon match, the outcome is scored against decentralized oracle feeds and recorded on the public BSC result ledger (0x77511fEFF4c0CA8bD5aeA8d64dC6a8dAe88C0744).
Cryptographic Guarantee
Because C is committed to BSC Mainnet prior to price outcome, the agent cannot retroactively alter its trade prediction or claim calls it did not commit. A stranger can audit the entire track record on BscScan with zero trust assumptions.

Pillar II: Chain-Anchored Risk Governance (`RiskGovernor.sol`)

Automated trading agents frequently fail due to uncontrolled drawdown during market regime shifts. Aureus Agent enforces programmatic capital preservation via RiskGovernor.sol (deployed on BSC Mainnet at 0xFACBc0a9b5a7dd34BfD0B91e1102dF4E72b9e43f).

The contract maintains an immutable risk ceiling where maxDrawdownBps = 1400 (14.0%). Account high-water mark equity is continuously recorded by an automated keeper (0x064Af3880d562720963bba400B51F95d45AF91d3). If drawdown exceeds 14%, the contract automatically transitions to the HALTED state, revoking token approvals on-chain.

Fractional Kelly Allocation Formula: f* = min( κ · [ (p · b - q) / b ], f_drawdown_ceiling )
where: p = 0.4992 (empirical win rate), q = 0.5008, b = 1.82 (payoff ratio), κ = 0.25 (quarter-Kelly safety factor)

The internal sizing engine sizes each leg so that a sequence of adverse outcomes stops trading before the 14% on-chain threshold is reached, providing a double-layered defense mechanism.

Pillar III: Fail-Closed Pre-Flight Security Solver

Prior to broadcasting any DEX transaction or granting approvals, the autonomous execution loop passes the order payload through tx_security_solver.py. Execution aborts immediately if any check fails:

Security Gate Evaluation Methodology Pass Criteria & Enforcement
1. Honeypot & Tax Guard Local EVM fork simulation of buy/sell transfers Combined buy/sell tax ≤ 2.0%; transfer function must not revert.
2. Allowance Containment On-chain query of ERC-20 allowances on BSC Strictly zero unlimited approvals (2^256-1); exact trade amount only.
3. Dynamic Slippage Cap PancakeSwap pool depth & price impact calculation Max price slippage ≤ 0.50% based on simulated swap output.
4. Pre-Flight Call Trace eth_call gas consumption & balance delta verification Execution gas ≤ 350,000 wei; expected asset balance must increase.
5. MEV & Frontrunning Guard Private validator RPC submission Bypasses public mempool; rejects transactions when spread > 0.2%.
6. Oracle Deviation Gate PancakeSwap spot price vs. Chainlink/Pyth price feed DEX spread |Pspot - Poracle| must not exceed 0.80%.
